注册与登录（学生册 · 一）

三种登录方式（统一入口 /reg）

点击任意页面的「登录/注册」，都会进入 /reg 一站式页面，含三个标签：

方式怎么用说明
注册账号输入邮箱 → 收 6 位数字验证码（5 分钟内有效，输错 5 次作废）→ 设置用户名和密码单邮箱 60 秒只能发一次，同 IP 每小时最多 20 次；注册成功自动登录并跳转入门训练路线
验证码登录输入已注册邮箱 + 验证码免密快速登录，验证码与注册码互不通用
密码登录用户名 + 密码即 Hydro 原生 /login；支持「记住我」、两步验证（TOTP/通行密钥）
  • 用户名规则：3~31 个字符（或恰好 2 个汉字）；注册后不能自行改名，找管理员走用户管理页改名。
  • 也支持 GitHub 登录（登录页的 GitHub 按钮）：授权后若是新用户会进入补全用户名/密码步骤。
  • 忘记密码：/lostpass 输入注册邮箱，重置链接由站内 Gmail 通道发出（注意查收垃圾箱）。
  • 注册后你已自动加入 system 域与 poj 域（排名生效的前提）。

做题与判题（学生册 · 二）

找题

  • 题库：支持搜索和筛选，例如 ?q=difficulty:1 按难度 1~10 筛选，?q=category:动态规划 按算法标签筛选；想随机刷题可访问 /problem/random（页脚「随机一题」直达）。
  • 题目页含题面、样例、提交记录与题解入口（/p/题号/solution，做完再看题解是好习惯）。

提交

  • 在题目页选择语言提交。本站 system 域开放语言：C (c)、C++17 (cc.cc17 / cc.cc17o2)、Python 3、Java。
  • 远程评测题（POJ 域、一本通 ybtbas、深入浅出 srqc 系列）可选语言以题目页下拉框为准：srqc 深基系列只认 cc.cc17o2；POJ 认 c / cc.cc98 / java。
  • 提交后跳转到记录详情页，判题实时刷新（状态行旁的实时通道）；列表页同样实时。

判题状态一览（精确枚举）

状态码含义状态码含义
0等待中7编译错误（CE）
1答案正确（AC）8系统错误（可申诉/重判）
2答案错误（WA）9已取消
3超出时间限制（TLE）11Hack 成功
4超出内存限制（MLE）20/21/22判题中 / 编译中 / 已取到（判题机已领取任务；远程题在此停留较久）
5输出超出限制31格式错误（多/少空格换行等）
6运行时错误（RE，崩溃/越界）32/33Hack 成功 / 失败
  • 时间按 CPU 时间计；内存默认 256MB，题目 config 另行指定的以题目为准（本站绝大多数题为 512MB）。编译器版本与参数见 状态页。
  • 远程题（POJ / ybtbas / srqc）由远端评测机判题，出结果稍慢，状态 22 表示已送达远端。
  • 同一题重复 AC 不会重复计分/刷 RP；比赛中的提交与练习互不干扰。

输入输出约定

除非题目特别说明，一律从标准输入读、往标准输出写；行尾多余空格一般不敏感，但行数与换行必须一致。样例块就是判题数据的第一组，能过样例不等于 AC——请自己构造边界数据。

解锁规则（重要）

  • 章节是链式解锁：前一章「全部题目 AC」才点亮下一章（XCPC 的 5~8 章为并列支线，第 9 章需支线全通）。
  • 章内点开题目 → 提交 → AC，返回路线页即可看到进度；工作台（见下）能看全部路线的整体完成度。
  • 推荐路径：一本通入门 → 蓝桥杯（按比赛日程取舍）→ XCPC + 专题查漏。

入口：首页「训练路线」网格，或 /training 列表页。

比赛功能（学生册 · 四）

  • 比赛列表：周末常设「海拔周赛」等校内赛；重要比赛会提前在讨论区公告。
  • 报名：比赛详情页点「参加」（Attend）。未报名时无法在赛内提交。
  • 赛内提交：从比赛题目页提交会自动带上比赛标识（tid）；计分板实时更新。隐藏题在赛内以字母代号显示，不泄题面。
  • 计分板：ACM 赛制按题数与罚时排名；比赛页可勾选「仅显示自己」。
  • 提前离场：侧栏「提前结束」只结束你自己的比赛（此后不能再提交），不影响他人与榜单。
  • 赛后：题目自动公开（autoHide 比赛）；QQ 群会收到比赛终榜战报。
  • Rating：校内 rated 赛的 Rating 变动显示在个人页（/user/你的UID/rating）与 /rating 榜。

工作台与错题本（学生册 · 五）

  • 训练工作台：登录后自动汇总你在各条训练路线的章节进度、AC 率与最近提交，是每天打开的第一个页面。
  • 错题本：每次 WA 会自动收录；补题 AC 后自动标记「已解决」，也可手动更新/移除。刷错题 > 刷新题。
  • 工作台与错题本仅登录用户可见（未登录访问会先跳登录）。

积分 · 商店 · 徽章（学生册 · 六）

  • 赚积分：每道题首次 AC 按题目难度入账 1~10 分（难度 1 题=1 分，难度 10 题=10 分；远程题同算）。
  • 积分商店：用积分兑换站内徽章，兑换即永久持有；积分流水可查每一笔进出。

  • 榜单每页 100 人，自己的行会高亮并带「你」徽章；翻页外也有置顶行显示你的位置。

题库维护（管理员册 · 二）

三条导题通道

通道入口注意事项
FPS 包（HUSTOJ 等来源）POST /problem/import/fps（multipart 字段 file）zip 需先解出内层 XML（内置 zip 解析有 bug）；不按标题查重（重复导入会建空壳重复题）；会丢 <spj>——多解题需手工补 testlib checker；GBK 编码包可能塌字（#4142 事故）

规则与铁律

  • owner 铁律：批量导入一律用 uid3 服务号会话（或导入后把 owner 批量改回 1）——否则你的账号会焊进每道题的「上传者」公开字段。
  • 补测试数据：HTTP 上传打不进（postUpload 分发问题），走 CLI：ProblemModel.addTestdata(domainId, docId, 文件名, 内容)，同名即替换。
  • 多解题（答案不唯一）：上 testlib checker——testdata 放 spj.cc + config.yaml 写 checker_type: testlib / checker: spj.cc；部署前用 @hydrooj/hydrojudge/vendor/testlib/testlib.h 离线编译并做「正解 AC / 替代解 AC / 错解 WA」三态验证。已配 checker 的题：1259/1266/1341/1279/2836/3124/3183/4088 + #10003。
  • 重判：POST /record/:rid 带 operation=rejudge（302 即成功）；批量重判远程题会被 hydroac 拦截（远端题不允许批量重判）。
  • 题目字段：难度 1~10（`difficulty`）、算法标签（`tag` 数组，category: 可筛）；改题面/标题直写 DB 即时生效，无需重启。
  • 判题数据结构：每题 data[] 内 .in/.out 成对 + config.yaml（time/memory/checker）；etag 是存储路径 base64，可据此直读数据文件对拍。

  • 创建：POST /training/create，字段 title / content（计划页正文）/ description（列表导语）/ pin（0 或 1，UnsignedInt）/ dag（JSON 字符串：[{"_id":1,"title":"章名","requireNids":[],"pids":[3676,3677]}]，pids 为数字数组）。

比赛管理（管理员册 · 四）

建赛（POST /contest/create，operation=update）

字段：beginAtDate、beginAtTime、duration（小时）、title、content、rule（acm|oi）、pids（逗号分隔）、rated、autoHide、allowViewCode、allowPrint、keepScoreboardHidden、allowTeam。必须带 operation=update（v5 按 body.operation 映射 post<Operation> 方法，缺了就是 405）。

赛中管理

  • 报名：选手自行 Attend；operation=early_end 是按用户提前离场（只影响本人，不影响榜单）。
  • 全局提前结束：编辑比赛缩短时长（或直接 DB 改 tdoc.endAt，带备份）。注意 postUpdate 会删 autoHide 的 unhide 定时任务——把已开赛比赛改到「立即结束」时不会重建，题目将保持隐藏，需手工处理。
  • 现场投屏：realboard 走 WebSocket /realboard-conn（onsite 工具，无普通 HTTP 页）。
  • Rating：比赛结束的自动计算是上游 stub；真出 Rating 用 /manage/rating 的 CSV 导入流程人工跑。
  • 判题期间隐藏题以字母显示；比赛提交带 tid 与练习隔离（去重也互不干扰）。

判题系统与排障（管理员册 · 五）

  • 链路：提交 → task 队列 → hydrojudge（pm2 独立进程）取任务 → 编译/沙箱评测 → 写回 record + document.status（RP 数据源）。
  • 服务号与判题机文件通道：/judge/files（拉数据）、/judge/upload（回传）、WebSocket /judge/conn，全部需要 PRIV_JUDGE。
  • 卡记录排查：record 集合按 pid（数字 docId） 查（不是 docId 字段）；非终态（0/20/21/22）超 10 分钟即异常——远程题先查 ws.hydrooj.com 中继是否 200，再重投。
  • CLI 坑：hydrooj cli execute 会带内嵌判题守护，可能抢任务并在 CLI 退出时把任务掐成僵尸——判题类操作前用 OVERRIDE_CONFIG（disable: true）关内嵌 judge；cli 里的顶层代码必须是顶层 await 语句。
  • 判题后服务号的 AC 会写 psdoc——已由 swpu-ops 三层自洁自动清（hook 即时删 + 重算前清 + 每小时清扫），无需手工。
  • 队列健康：task 集合应为空；pm2 logs hydrooj-error 尾部只有互联网扫描器探测（phpinfo/.env 等假路径）和游客 4xx 属正常。

  • 部署铁律：仓库（github.com/11suixing11/dfacm-oj）跑 deploy/deploy.sh（同步→SHA 对账→唯一一次 pm2 restart→就绪探测→26 项冒烟）；先传完全部文件再 restart；restart 后等 ≥75 秒再验收（30 秒内可能仍打到旧进程）。

架构与鉴权（API 册 · 一）

请求链路

浏览器 →（Cloudflare 可选）→ Caddy :443（TLS/HTTP3、缓存头、登录注册收敛改写、/user/3 封禁）→ hydrooj（127.0.0.1:8888，路由 → Handler → Model → MongoDB）→ hydrojudge（独立进程，经 /judge/files、/judge/upload 与 WebSocket /judge/conn 取任务回结果）；远程题走出站中继 wss://ws.hydrooj.com（ybtbas/srqc）与 POJ 直连。

鉴权模型

  • 会话：登录后种 HttpOnly Cookie sid + sid.sig（JS 读不到，落地页登录态靠探测导航 DOM 判断）。
  • 权限：PERM_* 为域级可配置权限（角色矩阵），PRIV_* 为全局权限位（priv=-1 为超管）。全表「权限」列为路由声明值；未声明的按 Handler 内 checkPriv 运行时判定。
  • 域前缀：几乎所有路由同时可经 /d/:domain 访问（如 /d/poj/p/P1000、/d/:domain/record-conn）。
  • operation 分发：POST 请求在 body 带 operation=xxx 时映射到 Handler 的 postXxx 方法（比赛建赛 405 问题的根因即漏带 operation）。
  • sudo：敏感管理页要求 sudo 态——先 GET 一次目标页（写 sudoArgs）再 POST /user/sudo（password），1 小时有效。
  • WebSocket 网关：/websocket 需要 x-hydro-websocket-gateway 头与 system.websocket.secret 比对；页面级 ws（record-conn 等）用会话 Cookie 鉴权。
  • 服务号：判题机账号（PRIV_JUDGE）走 /judge/* 三件套；对外一切身份页面均不可见。

  • 播报类集成不走 HTTP：QQ 机器人用只读 Mongo 账号直连（15 秒增量水位 + 非终态近窗复查），登录墙零改动、不给 Web 层加压。

# 训练计划流程（F3）

## 输入与日期

复用会话中的比赛日期、薄弱点与每日可用分钟数，水平可选。缺项或日期有歧义时一次性补问；比赛日期须含年份，固定长度计划还须明确起始日，或确认倒排至比赛前一天。补问后结束本次回复，不在末尾预估 D、阶段或赛事日程。每日分钟数须为正数，水平未知时保守安排并标明。

常规计划输出基准日与比赛日，D = 比赛日减基准日，逐日表只列基准日至比赛前一天的D个训练日，赛前准备也放进最后训练日的预算，不为容纳准备再加比赛日。已确认的固定窗口按用户起止排，另列实际距比赛天数；若窗口越过比赛日或与用户要求冲突，先澄清。过去日期需核对；D=0 只安排当天预算内的短复习与准备，不排新题或整题重做。

按 [plan-presets.md](plan-presets.md) 选阶段：1≤D<7 为薄弱点专项+限时模拟/复习；D≥7 为基础巩固→专题突破→模拟冲刺。最大余数法取整：先下整，再按余数从大到小补天，平局按阶段顺序，总和等于训练天数；零天阶段省略，日期连续且不重叠。固定窗口使用窗口长度分阶段，不把长度冒充距比赛天数。

## 从任务生成逐日表

1. **先分分钟，再计题**。按阶段模板的单题预计耗时排任务，每日读题、实现、样例/边界核对、复盘和准备的分钟总和不超过预算。跨天时段合计覆盖该题预计耗时；若用更快估计，给出用户实际速度依据，不因为叫“模板题”就降低难度耗时。时间不足时减少题量或延后专题，保留实现和验证。仅读题、思路或部分实现计计划新题0；安排完整实现与核对的完成日记计划新题1，实际执行未完成可为0，二者分开。未知成绩的模拟/重访才列条件范围，不把普通完整练习的计划数改成范围。未排足预计分钟的题计划计0，不以“若学得快则完成”列成条件新题；实际提前完成以后再依据执行记录统计。
2. **稳定题目身份**。每道不同题取任务名，如“背包K1”（明确是计划编号而非OJ题号），记录考点、难度与第一次安排日期。表中每个重访行须直接写“原日期+考点+任务名”，例如“重访04-08背包K1”，不能留成之后再选的“薄弱模板”。模拟每道题也单独命名，如第一场的S1-1背包、S1-2最短路，场次名不能代替题目身份；后续只补/重做其中明确列出的任务。每题首次完成只计一次；同题滚动数组优化计重做，新变式须说明不同题目目标。确定计划新题数从逐日列相加，条件范围另列；实际执行遇到未完成时，将原日实际完成数改为0，不能保留原日的计划1再加补题1。
3. **专题范围**。先覆盖每个薄弱方向，再按薄弱程度分配时间；同等薄弱时轮转。“DP/图论”可选择代表性子考点并说明范围。分钟或天数不足时，列本期实现、只做概念理解、延后三类，不声称全部突破。
4. **题目来源**。读取 [topic-verification.md](topic-verification.md) 和 [topic-map.json](topic-map.json)。当前内置题单较小，直接读取即可；所有条目待核验时写“暂无已核实的内置推荐”，用表内考点任务名让用户提供题面或自选，不启动推荐脚本。只有存在可用核验条目、确需筛选时才可选 `python -X utf8 -B scripts/topic_catalog.py recommend --topics 背包 最短路`（按实际考点改参数），同目的只调用一次；无输出/报错就按已读JSON处理，不改命令或重定向。只推荐 `verified: true` 且有匹配当前条目的开发者人工 `verification`，按来源+题号去重并排除已做题。整份计划包括结尾均不附模型自选题号，即使注明“请自行核对”也不用。没有历史错题时，重访本计划任务，不编造旧错题。
5. **模拟与补题**。每场列拟选题数、组成和任务名，题集由用户提供或自选，不声称已有赛题。无成绩时，K道不同模拟题的首次完成范围为0～K；K未知则待选后统计，不填正数下界。补题沿用模拟题名，累计按不同题目去重，不相加模拟日与补题日的范围上界。每段列诊断、实现、核对/记录的分钟，预算不足用分段限时训练；未知完成的模拟题不能直接变成确定“错题重做”。
6. **目标和交付对齐**。各阶段给周目标或阶段目标、检验标准和新题小计。思路理解以状态/转移讲清为标准，计新题0；只排一题不要求两题独立AC。无需预设必有卡点，顺利完成可记录“无”。AC率和排名趋势须等真实OJ记录后统计。

## 续作与重做

重访必须落到原日期、考点与任务名，不能只写“前几天未通过题”或“同日薄弱模板”。引用实际错题本/用户记录，或本计划先前的任务，不能编造历史失败。

未来任务结果未知时，写互斥分支：原日已首次完成→重做，只计重做；尚未首次完成→续作，完成当天才计新题；没有可做内容或无需重做→回顾该任务的概念/模板，计数均0。未知分支不同时加进小计。

分支要写在逐日表的计数格内，不能只在表后说明。重访一个完成状态未知的任务时，新题格写“未完成→续作0～1；已完成→0”，重做格写“已完成→重做1；未完成→0”；只回顾时两格都0。重访k个不同任务时上界为k，仍按互斥分支分开。**补题行固定写新题0是错误的**，除非明确只重做已完成题；不重复计数指全期去重，不代表补完当天不能首次计1。

小计分两种：原本安排完整首次实现的任务属于计划新题总数，延期只是把完成日移动，不另增全期计划新题；模拟题原结果未知，模拟+补题按同一任务名累计0～K。每日续作范围不能再加到已有计划新题总数上。如此逐日格、阶段小计、全期累计都表达同一题目状态。

例如“重访2027-04-08的背包K1，共60分钟：诊断/回顾10+实现40+样例核对/记录10”。K1已首次完成时，新题0、重做计划1；否则续作，新题0～1、重做0。若把该题安排过多天，累计仍只计一个首次完成。

### 计数示例

下面是模拟与补题的局部示例，不是整份训练计划。M1/M2是两道不同的计划任务，不是OJ题号；题面由用户提供或自选。没有历史成绩，不设完成下界。

| 日期 | 任务与分钟 | 新题 | 重做 |
|---|---|---|---|
| 2027-04-08 | 模拟：背包M1 50+最短路M2 50+复盘20 | 0～2，按实际首次完成 | 0 |
| 2027-04-09 | 重访04-08的M1：回顾10+实现40+核对10；重访同日M2：同样60 | 原日未完成的任务补完才计1 | 原日已完成的任务重做才计1 |

两天合计新题范围0～2，重做范围0～2，均不是已达成结果，不能把两个上界称为完成4道新题。后一天两题均已完成且无需重做时，回顾这两题的易错点占用原时段，计数均0。

## 输出前核对

以逐日表为唯一账本核对日期、分钟、题目身份、完成状态与目标，再写阶段小计。每个重访行能在先前表行查到同一任务名、考点和日期，且给出完成/未完成/只回顾的分支；每个模拟组有具体任务名与组成，后续引用不变。确定计划数与条件模拟/续作范围分开列，累计按不同题目去重；清单只索引表内任务，不另增题量。每个薄弱点有具体任务，延后项不混入表。题单为空时检查整份回复的表、清单、结尾建议和脚注都没有模型自选具体题号；“例如某平台题号、请自行核对”仍是推荐，改成表内任务名。局部算法提示也须正确，例如0–1背包 `j` 从容量倒序到物品体积 `t`，`j<t` 不访问 `dp[j-t]`，`t>T` 跳过。

## 可选日期与预算辅助

常规日期差、阶段取整和分钟直接核算即可。有Python时可选用 [scripts/plan_budget.py](../scripts/plan_budget.py)，按实际技能目录解析路径：

```powershell
python -X utf8 -B scripts/plan_budget.py --today 2026-10-21 --contest 2026-11-20 --daily-minutes 90 --beginner 1 --basic 1
```

`--today`默认本机今天。JSON提供D、连续阶段和单题拆分所需最少天数；题量参数只校验某一天，超预算退出1，参数/过去日期错误退出2。脚本不选题、不证明学习结果。

用户已有逐日JSON账本时可加 `--schedule <文件路径>`，只读校核日期、分钟、题目身份与条件计数。根对象含 `problems`（任务名→`topic`/`level`，历史完成可填`completed_on`）和 `days`（每行`date`/`tasks`）。任务含`label`、`minutes`、`kind`：`study`不计题；`start`/`finish`带`problem`；`redo`/`revisit`另带`origin_date`；`mock`带`problems`数组。条件补题用`revisit`，禁止同题再次`finish`。脚本检查计划声明，单题预计耗时另核算。普通聊天无需创建JSON或展示这个内部格式。

一次同目的工具调用无输出或报错后停止该调用，按日期和预算直接核算，不换命令、探测终端或创建重定向文件；未得到结果不称已用脚本验证。用户要求只聊天时全部计划留在聊天。

## 输出形式

- 总览：基准日、比赛日、D或已确认固定窗口、阶段日期/天数、每日预算、水平、专题范围、题目来源。
- 一份逐日表：日期／考点与任务名／具体任务及分钟拆分／计划新题／重做。跨天和重访沿用任务名，条件用互斥分支说明。
- 每阶段目标、检验标准和小计；确定计划数与条件范围分开列，累计按不同题目去重。题目清单仅索引表中任务，不重复抄表。难度题量配比可省略；若报告实际配比，按已列任务逐题统计，不能直接沿用阶段建议比例。
- 需要延后的专题和执行调整：超时续作、真实完成/OJ统计、样例与边界验证。

直接呈现计划，不复述资源加载过程或抄写内部规则。长计划可用周表与明确逐日循环规则，但每个训练日期都须能对应任务和分钟；短计划直接列日表。D=0用当天分钟表和简短检验标准即可，每个动作包括小样例核对均占用预算；没有历史题目时回顾核心转移并构造小输入，不说“你已写过的题”。各小计和建议只写一次，不在清单、说明、结尾重复整表。缺项时只补问，不套完整计划格式。

# 错题复盘流程（F2）

## 触发
用户提供题面或题号+来源，描述错误原因（可附当时代码），说"记一道错题 / 复盘这道题"。

## 处理流程

1. 先识别仅在聊天复盘、录入、更新、汇总或晒卡请求。只说“复盘这道题”时在聊天给出下方结构化内容，不创建笔记；明确说“记一道错题 / 录入 / 保存到错题本 / 更新记录”才按第4步写入。汇总与晒卡可以单独执行，不要求重新提供题面；录入时复用当前会话已给出的信息。题号本身不能证明算法标签、难度、错因或正确思路，缺少依据的字段标为"待补充"。只有"没开 long long"之类自述时，错因分析写"用户自述未用 long long，具体变量、数值范围及溢出证据待补充"；不能据此声称该题答案超过 int、已确认发生溢出或修正后已通过。若分类为溢出，标明这是按用户自述暂记的类型。
2. **归一算法标签**：从固定标签集选 1-2 个（与模板库考点对齐）：
   二分 / 贪心 / 前缀和与差分 / 双指针与滑动窗口 / 并查集 / 树状数组 / 线段树 / ST表 / 单调栈队列 / 最短路 / 最小生成树 / 拓扑排序 / Tarjan连通性 / 线性DP / 背包 / 区间DP / 树形DP / 状压DP / 数位DP / KMP / 字符串Hash / Trie / 数论 / DFS-BFS搜索 / 模拟
3. **判定错误类型**（固定枚举，单选）：思路错误 / 边界 / 溢出 / 复杂度超限 / 实现细节 / 读题偏差。选本次有依据的主要错因；尚不能判断时写"待补充"。
4. **生成或更新错题笔记（仅明确录入/保存/更新请求）**：按下方固定字段写入用户当前项目根目录 `mistake-notebook.md`，不是技能安装目录。先读取现有文件；不存在则创建，新题接在文末，保留其他记录。仅在聊天复盘时跳过写入，在回复中呈现完整笔记内容；录入后也须展示受影响条目的内容，不能只报告“已保存”。
   - 以来源 + 题号识别同题（忽略首尾空格、拉丁字母大小写）；同题再次录入时更新原条目，保留首次日期，在错因分析内追加带日期的复盘记录与本次修正，不新增同题标题。完全相同的重复请求不改文件；补齐题面、代码或实际调试证据后，才能把"待补充"改为有依据的结论。
   - 没有题号时使用明确标为"本地"的临时编号；仅凭相同题名不合并题目。更新此类条目时按已有本地编号或用户明确指定的记录定位，不能把临时编号当作 OJ 题号推荐。
   - 写入后重新读取受影响条目，核对下方八个字段名、内容与实际路径再报告"已新增 / 已更新"。无法识别用户项目、没有写入工具或写入失败时，直接给出完整可保存的 Markdown 与"尚未写入"说明，不能仅称内容已准备好而省略正文；权限拒绝后不换工具绕过，也不把提供备份文本延后到再次确认之后。
5. **同类题推荐**：读取 [topic-verification.md](topic-verification.md) 与 `references/topic-map.json`，按算法标签筛选 `verified: true` 且有匹配当前条目的开发者人工 `verification` 核验记录，再取 2-3 题；排除当前错题并按来源 + 题号跨标签去重。不足时如实给出可用数量。只引用这些条目的来源、题号、标题、难度与推荐理由；预填待核实条目不用于推荐。无可用条目时写"暂无已核实的内置推荐"，给同考点练习方向。有 Python 时可从技能根调用 `python -X utf8 scripts/topic_catalog.py recommend --topics 背包 最短路 --limit 3 --exclude 洛谷/P1048`，按实际标签/当前题替换参数，不将示例作为本次推荐。
6. 用户说"生成晒卡" → 按晒卡版式额外输出一份紧凑分享版；仅生成晒卡不重复写入笔记。

## 回答呈现

直接从复盘条目、汇总结果或晒卡正文开始。普通聊天复盘无需声明“仅聊天 / 未写入”，也不追加保存操作建议；内容中不报告技能流程、资源路径或核验字段名。暂无可推荐条目时直接说明“暂无已核实的内置推荐”并给练习方向即可。明确请求写入时，可简短确认实际结果；写入失败仍按第4步给完整备份正文和失败说明。

## 错题笔记字段（逐字固定）

```markdown
### [来源/题号] 题目名
- 日期：（首次录入日期 YYYY-MM-DD；后续复盘日期写入错因分析）
- 算法标签：（如 背包 / 最短路；无依据时待补充）
- 难度：（入门/基础/进阶；无依据时待补充）
- 错误类型：思路错误 / 边界 / 溢出 / 复杂度超限 / 实现细节 / 读题偏差
- 错因分析：（2-3 句）
- 正确思路关键步骤：
- 易错点警示：
- 同类题推荐：（来自 references/topic-map.json 的已核实条目，目标 2-3 题；不足时如实说明）
```

## 汇总查询

用户说"按考点汇总"或"按错误类型汇总" → 读取实际错题本，输出唯一题目总数、各分组题数与明细（来源/题号 + 一句话错因）。按当前字段统计，同题的复盘历史不增加题数；旧文件若已重复录入同来源/题号，汇总时合并计数并说明。多标签条目可出现在多个考点组，说明分组计数之和可能大于唯一题目总数；待补充字段单独分组。文件不存在或为空时说明尚无记录，不能用聊天记忆冒充文件统计。

## 晒卡版式（可选输出，用户要求时）

从当前已提供的复盘或指定错题记录生成；用户未指定且存在多题时先确认目标。字段不全时保留"待补充"，不为凑齐三条思路编造内容；晒卡只整理复盘，不表示已 AC，也不自动发布。

```
📋【算法错题复盘】题目名（来源/题号）
🎯 考点：算法标签
💥 一句话错因：……
✅ 正确思路 3 条：
1. …
2. …
3. …
⚠️ 下次先检查：易错点
#算法竞赛 #错题复盘 #ACM
```

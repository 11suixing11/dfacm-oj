# 数据与开源边界

公开仓库只包含源码、人工构造的演示数据、测试、空配置示例和通用说明。选手源码、用户资料、审核备注、AI 输出、真实提交链接、部署日志、服务器地址、会话、数据库导出和个人电脑路径不属于公开材料。

## 运行时数据

生产插件在 OJ 服务器内读取 Hydro 提交记录和已有的 `dfacm_assistant_jobs` 完整解答。不把源码发送给 GitHub 或第三方检测 API。使用其他题目助手时，需要自行适配来源格式；没有该来源集合时，来源匹配不会凭空提供证据。

- `dfacm_ai_watch_reports` 保存提交指纹、线索和人工复核记录，不保存提交源码原文。
- `dfacm_ai_watch_sources` 保存站内 AI 完整输出，用于管理员对照。
- `dfacm_ai_watch_state` 保存扫描检查点和采集心跳。

报告与来源默认保留 30 天，接口排除过期数据，Mongo TTL 索引异步删除；每份报告最多保留 20 次复核记录。管理员接口检查 `PRIV_MANAGE_ALL_DOMAIN` 权限，写入检查会话与用户绑定的 CSRF token。备份中的历史数据需要由站点管理员单独管理。

## 提交与发布

`.gitignore` 忽略本地配置、凭据、私有材料、数据库导出和验收结果，但不会删除已提交文件或 Git 历史。不得通过 `git add -f` 绕过这些规则。发布脚本只打包 `scripts/public-files.cjs` 的明确文件清单，目录中额外出现的日志、密钥或数据文件不会被递归打包。

发布前运行：

```bash
node scripts/check-public.cjs
node scripts/check-public.cjs --git
```

第二个命令核对暂存内容、提交历史、文件清单与提交邮箱，要求使用 GitHub 的 `users.noreply.github.com` 邮箱。新增公共文件时需明确更新公开清单。检查是辅助措施，不能保证识别每一种隐私信息；Issue、PR、提交说明和截图也需要检查，只使用模拟数据。

若凭据曾进入 Git 历史或公开附件，应先撤销或更换凭据，再清理相关历史。仅修改 `.gitignore` 或删除最新版本中的文件不足以撤销泄露。

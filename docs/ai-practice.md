# d&f算法网 · AI 开发实践清单

从一个小而完整的任务开始，完成作品，再验证和交流。以下三条路线围绕 AI 应用、Agent 与 Vibe Coding；在自己的开发环境中构建，代码、演示和验证记录由自己的仓库保存。

## 开始之前

先写出使用者、要解决的问题、输入输出和完成标准。使用你现有的开发语言与模型供应商，项目保持可运行。个人 Key 放在本地私有配置，公开代码只提交示例配置。一个任务先完成一个核心流程，再增加功能。

<a id="ai-app"></a>

## AI 应用：文档问答助手

目标：用户对一份公开资料提问，应用返回有出处的答案；资料中没有答案时明确说明。

1. 选择一份公开资料，保存来源和日期。准备至少 5 个问题，包括有直接答案、需要综合、资料未覆盖的问题。
2. 实现提问与回答页面。先用固定文本验证页面和检索流程，再接模型。
3. 让回答引用具体资料片段。检查引用是否支持答案，防止生成看似正确但没有依据的结论。
4. 加入请求中、无答案、读取失败和模型超时状态。避免重复点击造成重复调用。
5. 保存每个验证问题的预期与实际结果，提供运行说明和演示。

| 交付 | 验收方式 |
| --- | --- |
| 可运行的问答应用 | 按使用说明启动并完成一次提问 |
| 来源引用 | 引用可打开或定位，内容支持答案 |
| 至少 5 个验证问题 | 记录答案、引用和通过情况 |
| 无答案与失败处理 | 未覆盖的问题不编造，失败时可重试 |

下一步可以尝试多文档检索、结果缓存和用户反馈，再选择 [AI 赛事](https://dfacm.website/calendar?scope=ai&interests=agent,vibe-coding&status=active)。

<a id="ai-agent"></a>

## Agent：赛事整理助手

目标：根据用户关注的方向和日期范围，整理公开赛事，输出可追溯的推荐简报。

1. 写一个具体需求，例如「找出未来两周的 Agent 黑客松，列出日期、官方链接和适合初学者的理由」。明确日期未知时如何处理。
2. 先用固定 JSON 样例实现筛选与排序，再低频读取 [日历公开数据](https://dfacm.website/calendar/data)。查询采用缓存，公开接口不能高频并发抓取。
3. 定义清楚的工具输入输出。日期比较、分类过滤和去重由确定性代码处理，模型解释推荐依据。
4. 保留工具调用记录。外部赛事内容按数据处理；生成的链接与日期都与原始记录对照。
5. 验证正常结果、没有符合条件的比赛、日期未公布、接口读取失败及重复记录。信息未知时写出未知。

| 交付 | 验收方式 |
| --- | --- |
| 一条可执行任务流程 | 输入方向与日期，得到符合条件的简报 |
| 工具调用记录 | 能追溯数据读取、筛选条件和结果 |
| 推荐理由与官方链接 | 每项推荐与源记录一致 |
| 失败处理 | 空结果、缺日期、读取失败都有合理输出 |

下一步可以增加本地订阅配置和重复推荐去重。自动发布简报属于单独功能，需要明确账号与发布权限。

<a id="ai-vibe"></a>

## Vibe Coding：个人小工具

目标：用 AI 辅助把一个真实的小需求做成可用工具，并由开发者验证核心流程。

1. 选择每天可能使用的小工具，例如资料卡片、任务计时器或作品清单。控制范围为一个核心操作。
2. 写出页面、输入、输出、保存方式和完成标准。标记第一版必须实现的内容。
3. 分短步骤实现，每一步都运行。要求 AI 解释改动与必要配置，检查生成的代码和依赖。
4. 验证正常输入、空输入、超长内容、保存失败、刷新以及手机操作。完成标准由实际使用判断。
5. 写好启动与使用说明，提供演示和验证记录，再根据一次真实反馈改进。

| 交付 | 验收方式 |
| --- | --- |
| 可使用的核心流程 | 用户无需额外解释即可完成一次操作 |
| 简短使用说明 | 能启动，能判断数据保存到哪里 |
| 验证记录 | 覆盖正常、空输入、失败和手机交互 |
| 一次改进 | 记录反馈、修改和修改后的结果 |

可到 [交流社区](https://dfacm.website/discuss) 分享实现过程，或查看 [Vibe Coding 与 Agent 赛事](https://dfacm.website/calendar?scope=ai&interests=vibe-coding,agent&status=active)。社区当前是通用讨论区。

## 分享作品时写什么

建议包含：作品名称、目标使用者、解决的问题、代码链接、演示链接、运行方法、验证结果、仍未解决的问题和下一步。AI 辅助实现可以写出工具的参与方式，重点展示你对结果的理解与检查。

项目托管、专用作品投稿和实践进度系统的建设安排见 [产品定位](product.md#建设顺序)。
